# 开发者日志（devlog）

比赛要求**不少于 3 篇公开开发者日志**，发布到小红书 / B站 / 小黑盒任一渠道，并回填链接。本目录存底稿，正式发布后再补链接。

## 命名

```
2026-12-01-devlog-01.md
2026-12-03-devlog-02.md
2026-12-05-devlog-03.md
```

日期用发布当天，序号按顺序递增。**不要**用「第一篇」「终稿」这类名字，排序会乱。

## 三篇的时间点与主题

| 篇 | 建议日期 | 主题 | 为什么放这天 |
| --- | --- | --- | --- |
| 01 | 12.01 | 从零到能动：项目骨架、分工、第一版可跑画面 | 有 `v0.1-d4` 标签，说得清“做出来了什么” |
| 02 | 12.03 | 最难的那个坑：一场具体的技术问题怎么解决的 | 读者最爱看踩坑，比罗列功能有信息量 |
| 03 | 12.05 | 收尾：玩法闭环、AI 怎么用、参赛体会 | 正好配合提交，能给作品导流 |

## 每篇的结构（照这个写，别自由发挥）

1. **对外标题**：一句具体的话，不要“开发日志 01”。例：`塔朝着哪边开火？我们把择向逻辑重写了三遍`
2. **开头两行**：这周做到哪一步、玩家现在能玩到什么
3. **主体**：一件事讲透。要么讲一个坑（现象 → 排查 → 结论），要么讲一个设计取舍（两个方案 → 选哪个 → 为什么）
4. **配图**：截图或录屏 GIF，至少一张。没有图的日志基本没人看
5. **结尾**：下一步做什么 + 一句 AI 使用说明

## 硬性要求

- 每篇都要有一句 AI 使用说明，例如「本文技术方案由 AI 辅助整理，代码由本人编写并调试」。比赛有《AI 使用与素材声明》，日志里漏写会被认为口径不一致。
- 不写队友的真实姓名、住址、学校以外的个人信息。
- 不写“内部吵架”“谁拖了进度”这类内容，公开材料只谈事。
- 数值可以写，但改过的旧数值不要写，避免和最终版本冲突。
