# 仓库搭建与协作规范

本文件写给《守望》项目组全体：仓库怎么建、队友怎么进、每天怎么提交、提交日怎么同步到 AtomGit。凡与本文冲突的做法，以本文为准。

## 零、环境说明

本机未安装 Git for Windows，PowerShell 里直接敲 `git` 会报“无法识别”。有两个选择：

- 用 GitHub Desktop 的全部图形操作（推荐，够用）。
- 想用命令行：GitHub Desktop 自带 git，路径为
  `C:\Users\lenovo\AppData\Local\GitHubDesktop\app-3.6.10\resources\app\git\cmd\git.exe`，
  在 PowerShell 里先设一次别名：

  ```powershell
  Set-Alias git "C:\Users\lenovo\AppData\Local\GitHubDesktop\app-3.6.10\resources\app\git\cmd\git.exe"
  ```

  或直接装 Git for Windows（自带 Git Bash 与 PATH 配置），队友按装 Git 更省事。

本文出现的 `git` 命令，均指在这两种环境下执行。

## 一、建库前的两个决定

1. 仓库设为 **Public**。比赛要求公开源码，公开仓库的协作者人数也不受限制；私有仓库免费版最多 3 个协作者，5–6 人的队伍会撞上限。
2. 仓库名用**纯英文**，避免 AtomGit 同步与命令行转义问题。建议 `shouwang`，备选 `osgj2026-shouwang`。

## 二、本地建库步骤（GitHub Desktop）

推荐先用本地已有目录建库，再发布，避免空仓库首次提交的坑。

1. 本地目录已按约定结构备好（见本项目根目录）。
2. GitHub Desktop → `File` → `Add existing repository`（若本地已有 `.git`）或 `File` → `New repository`（若尚未初始化），Name 填 `shouwang`，Local path 指向本目录。
3. 提交首次内容：Summary 写 `init: 项目骨架与规范文档`，点 `Commit to main`。
4. 点 `Publish repository`，**取消勾选 `Keep this code private`**。

首次提交前请确认 `.gitignore` 已生效：左下角 Changes 里不应出现 `.godot/`。若出现，先删除再跟踪：

```powershell
git rm -r --cached .godot
```

## 三、邀请队友（Collaborator 方案）

GitHub Desktop 没有成员管理入口，需在浏览器操作。

1. 打开 `https://github.com/<你的用户名>/shouwang/settings/access`。
2. 点 **Add people**，输入队友的 GitHub 用户名或邮箱，一次可加多人。
3. 权限**只给 Write**，不要给 Admin。合并权集中在队长手里。
4. 队友收到邮件邀请，点 Accept 后即可直接 clone 本仓库，**不需要 fork**。
5. 加完人去 `Settings` → `Branches` → `Add branch protection rule`：
   - Branch name pattern 填 `main`
   - 勾选 `Require a pull request before merging`
   - `Require approvals` 设为 1
6. （可选）`Settings` → `General` → Danger Zone 里确认仓库为 Public。

**发给队友的邀请话术**：

> 仓库地址：https://github.com/xxx/shouwang
> 已把你加为协作者，邮件里点接受就能看到（找不到就看垃圾箱）。
> 本地流程：`git clone` → `git switch -c feat/p1-battle`（P2 用 `feat/p2-economy`，P3 用 `feat/p3-flow`）。
> 每天收工前 push 一次，合并走 PR 到 main，我来合。main 有保护，别直推。

**队友首次操作（Windows PowerShell）**：

```powershell
git clone https://github.com/xxx/shouwang.git
cd shouwang
git switch -c feat/p1-battle
```

用 GitHub Desktop 的话：`File` → `Clone repository` → 选 `shouwang` → `Branch` → `New branch` 填 `feat/p1-battle`。

## 四、分支、提交与标签约定

- 分支：`feat/p1-*`、`feat/p2-*`、`feat/p3-*`，缺陷修复用 `fix/*`，文档用 `docs/*`。
- 一个分支只做一件事，做完就发 PR，不要攒到第三天。
- 提交信息格式：`P1: 塔位合法性判定与建造扣费`（域前缀 + 做了什么）。
- 里程碑打标签：
  - `v0.1-d4`：D4 收工，能打完一关
  - `v0.2-d5`：D5 收工，跑通“胜利→商店→再胜”
  - `v1.0-submit`：提交版
- 禁止直接推 `main`；禁止强推（`--force`）；禁止把 `build/`、导出包、临时文件提交进仓库。

## 五、每日流程（三人一致）

1. 早上：`git switch main` → `git pull` → 切回自己分支 → `git merge main`，先吃掉别人的接口变更。
2. 开发：只动自己域内的文件；跨域需求发到群里，由负责人改。
3. 收工：`git add -A` → `git commit -m "P1: xxx"` → `git push`。
4. 每日收工由 P3 在合并后的分支上打包一次，全队在真机上运行当天版本；未运行视为未验收。

## 六、文件与素材规则

- 代码、场景、数据一律用 English 路径与文件名，避免跨平台与工具链问题。
- 图片、音频统一放 `assets/` 下对应子目录，并走 Git LFS（`.gitattributes` 已配置）；首次提交大文件时 GitHub Desktop 会提示启用 LFS，点同意。
- 第三方素材必须登记到 `docs/AI使用与素材声明.md`，写清来源、许可、是否改动。
- 策划案、分工方案等 PDF 放 `docs/`，不要散落在根目录。

## 七、AtomGit 同步（提交日前完成）

比赛以 AtomGit 仓库为准，GitHub 只作日常开发。本地仓库配两个远端：

```powershell
git remote add atomgit https://atomgit.com/<你的账号>/shouwang.git
git remote -v
```

日常只推 GitHub；提交日：

```powershell
git switch main
git pull
git tag v1.0-submit
git push origin main --tags
git push atomgit main --tags
```

注意事项：

- AtomGit 仓库必须包含**完整可运行源码**、`docs/AI使用与素材声明.md`，以及可运行发行版与启动说明（发行版可放 Release，不放仓库正文）。
- **不要在原子派内提交**，那边提交无效。
- 提交后版本锁定，赛期内不要再改 tag。
